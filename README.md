# CAPTCHA Guard — browser automation client

**CAPTCHA Guard** — экспериментальный проект для тестирования Cloudflare Turnstile на собственном сайте. В проекте есть тестовая веб-страница с CAPTCHA и отдельный C#-скрипт, который открывает её в браузере, взаимодействует с виджетом и получает результат проверки.

Этот репозиторий — основной: здесь подробно описаны браузерный скрипт и его запуск на VPS. Frontend и backend являются вспомогательными компонентами тестового стенда.

## Репозитории проекта

| Компонент | Назначение | Репозиторий |
|---|---|---|
| **Script** | Автоматизирует взаимодействие с тестовой страницей в Chrome | [captcha-guard-script](https://github.com/VitaliyArmss/captcha-guard-script) |
| Frontend | Страница с виджетом Cloudflare Turnstile | [captcha-guard-frontend](https://github.com/VitaliyArmss/captcha-guard-frontend) |
| Backend | Серверная проверка полученного CAPTCHA-токена | [captcha-guard-backend](https://github.com/VitaliyArmss/captcha-guard-backend) |

## Общая схема работы

Frontend отображает виджет Cloudflare Turnstile. После успешного прохождения проверки виджет передаёт токен frontend-приложению, которое отправляет его на backend. Backend проверяет токен через Cloudflare Siteverify API и возвращает результат.

Скрипт не реализует серверную валидацию CAPTCHA и не обращается к Siteverify напрямую. Он управляет браузером: открывает страницу, взаимодействует с виджетом, нажимает кнопку проверки на сайте и считывает отображённый результат.

## Скрипт: технологии и принцип работы

### Используемые технологии

- **C# / .NET 8** — язык и платформа консольного приложения.
- **Microsoft.Playwright 1.64.1** — запуск Chrome, работа с DOM, ожидание элементов и управление мышью.
- **Google Chrome Stable** — браузер, запускаемый через `Channel = "chrome"`.
- **CSS-селекторы и ARIA-атрибуты** — поиск элементов тестовой страницы и контейнера CAPTCHA.
- **Playwright Mouse API** — перемещение указателя и нажатия по координатам окна браузера.

Отдельная библиотека **Pixel Pointer** в проекте не используется. Под «пиксельным» управлением указателем здесь подразумевается получение координат элемента через `BoundingBoxAsync()` и последующее управление мышью через Playwright `page.Mouse`.

Скрипт также запускает Chromium с аргументом `--disable-blink-features=AutomationControlled`. Он изменяет один из браузерных признаков автоматизации, но сам по себе не гарантирует прохождение CAPTCHA.

### Последовательность работы

1. Скрипт считывает аргументы командной строки. По умолчанию используется режим `manual` и адрес `http://localhost:5173`.
2. Playwright запускает установленный Google Chrome в видимом режиме (`Headless = false`).
3. Создаётся постоянный browser context с профилем `CaptchaGuardProfile`, после чего открывается заданный URL.
4. Скрипт ожидает появления кнопки `#verify-button`.
5. Пока кнопка недоступна, скрипт ищет контейнер виджета по селектору:

   ```css
   div.widget-frame[aria-label='Cloudflare Turnstile CAPTCHA']
   ```

6. Через `BoundingBoxAsync()` получает положение и размер дочернего элемента контейнера. На основе этих данных рассчитывается точка взаимодействия с небольшим смещением по X и Y.
7. Указатель перемещается к рассчитанной точке несколькими шагами, после чего выполняется нажатие через `Mouse.DownAsync()` и `Mouse.UpAsync()`. Затем указатель уводится в другую область окна, а скрипт делает паузу.
8. Ожидание повторяется, пока кнопка не станет доступной или не истечёт лимит времени (до четырёх минут).
9. Если Cloudflare показывает интерактивный challenge, его можно пройти вручную в открытом окне Chrome. Скрипт не распознаёт изображения и не решает визуальные задания самостоятельно.
10. Когда кнопка становится активной, скрипт нажимает `#verify-button`. Frontend сайта отправляет полученный токен на backend.
11. Скрипт ожидает появления `#secret-output` и считывает его текст. Если сообщение не появилось, он получает диагностический текст из `#status`.

Таким образом, используются два способа взаимодействия с сайтом:

- **DOM:** поиск элементов, ожидание состояний кнопки и чтение результата;
- **координаты мыши:** вычисление позиции элемента и управление указателем через Playwright Mouse API.

### Аргументы командной строки

| Аргумент | Значение по умолчанию | Описание |
|---|---|---|
| `--mode` | `manual` | Режим запуска текущей версии скрипта |
| `--url` | `http://localhost:5173` | URL тестовой страницы |
| `--api` | — | Аргумент считывается, но в текущей версии не используется |

Пример запуска с адресом уже размещённого тестового сайта:

```bash
dotnet run -- --mode manual --url https://your-test-domain.example
```

## Запуск скрипта на VPS

### Почему нужны Xvfb и x11vnc

Скрипт запускает Chrome с `Headless = false`, поэтому ему нужен графический дисплей. На VPS обычно нет физического монитора и рабочего стола.

- **Xvfb** создаёт виртуальный X11-дисплей, на котором Chrome может открыть обычное графическое окно.
- **x11vnc** позволяет удалённо просматривать этот дисплей и при необходимости взаимодействовать с браузером.

Chrome при этом остаётся обычным графическим браузером, а не headless-процессом. x11vnc нужен для удалённого доступа к его окну; особенно это полезно, когда challenge требуется завершить вручную.

Инструкция ниже рассчитана на Ubuntu/Debian VPS архитектуры `amd64`.

### 1. Установка зависимостей

```bash
sudo apt update
sudo apt install -y xvfb x11vnc xauth dbus-x11 curl wget ca-certificates
```

Установите **.NET 8 SDK** и **Google Chrome Stable**. Скрипт использует `Channel = "chrome"`, поэтому Chromium, установленный только через Playwright, не заменяет установленный Google Chrome.

Пример установки Chrome:

```bash
wget -O /tmp/google-chrome-stable_current_amd64.deb \
  https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
sudo apt install -y /tmp/google-chrome-stable_current_amd64.deb
google-chrome --version
```

Рекомендуется запускать браузер и скрипт от отдельного непривилегированного пользователя, а не от `root`.

### 2. Запуск виртуального дисплея

Запустите Xvfb от имени пользователя, который будет запускать скрипт:

```bash
Xvfb :99 -screen 0 1920x1080x24 -ac -noreset \
  > /tmp/captcha-guard-xvfb.log 2>&1 &

export DISPLAY=:99
```

`DISPLAY=:99` указывает графическим приложениям использовать виртуальный экран. Разрешение можно изменить при необходимости.

Проверить запуск можно командой:

```bash
pgrep -a Xvfb
```

### 3. Запуск x11vnc

Этот шаг нужен только для удалённого просмотра окна Chrome и ручного взаимодействия с ним.

Создайте пароль VNC:

```bash
mkdir -p ~/.vnc
x11vnc -storepasswd
```

Запустите VNC-сервер на дисплее `:99`:

```bash
x11vnc -display :99 \
  -localhost \
  -forever \
  -shared \
  -rfbauth "$HOME/.vnc/passwd" \
  -rfbport 5900 \
  -noxdamage \
  > /tmp/captcha-guard-x11vnc.log 2>&1 &
```

Параметр `-localhost` ограничивает VNC локальным интерфейсом сервера. Для подключения с компьютера откройте SSH-туннель:

```bash
ssh -L 5900:127.0.0.1:5900 USER@VPS_HOST
```

После этого подключитесь VNC-клиентом к `127.0.0.1:5900`. Не открывайте порт `5900` напрямую в публичный интернет — используйте SSH-туннель и firewall.

### 4. Сборка и запуск скрипта

Склонируйте основной репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/VitaliyArmss/captcha-guard-script.git
cd captcha-guard-script
```

Восстановите зависимости и соберите приложение:

```bash
dotnet restore
dotnet build -c Release
```

Запустите скрипт, передав URL уже доступной тестовой страницы:

```bash
DISPLAY=:99 dotnet run -c Release -- \
  --mode manual \
  --url https://your-test-domain.example
```

Команду нужно выполнять от того же пользователя, которому принадлежит дисплей Xvfb. При запуске через другой shell или systemd unit передайте переменную окружения `DISPLAY=:99`.

> Frontend и backend в рамках этой инструкции не разворачиваются: предполагается, что тестовый сайт уже доступен по указанному URL и самостоятельно взаимодействует со своим API.

## Ограничения

- Скрипт рассчитан на конкретную структуру тестовой страницы и использует селекторы `#verify-button`, `#secret-output`, `#status` и `div.widget-frame[aria-label='Cloudflare Turnstile CAPTCHA']`.
- При изменении HTML-разметки страницы селекторы в `Program.cs` могут потребовать обновления.
- Ожидание готовности кнопки ограничено четырьмя минутами; ожидание результата — 30 секундами.
- Для запуска на сервере без физического дисплея требуется графическое окружение, например Xvfb.
- Управление мышью по координатам не гарантирует прохождение challenge. Результат зависит от конфигурации Cloudflare, домена и сценария проверки.
- Используйте проект только на собственном сайте или в среде, на тестирование которой у вас есть разрешение.
